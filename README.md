# Линия — замер скорости скачивания

Консольный инструмент, терминальный интерфейс и локальная веб-страница для измерения загрузки по выбранному URL. Каждый замер выполняет **10 последовательных HTTP-запросов** и полностью читает тело каждого ответа.

## Быстрый старт

Нужен Node.js 20.9+ и npm.

```bash
npm ci
npm run measure -- https://example.com/large-image.jpg
```

Адрес может вести на HTML-страницу, изображение или другой доступный ресурс. Для реального замера скорости лучше использовать большой файл. Для более устойчивого результата выберите файл размером хотя бы несколько мегабайт. Инструмент не меняет URL: некоторые сайты отклоняют незнакомые параметры. Для запроса свежего ответа отправляются заголовки `Cache-Control: no-cache` и `Pragma: no-cache`. Сервер всё равно может отдать кешированную копию.

## Режимы

| Режим | Команда | Что делает |
| --- | --- | --- |
| CLI | `npm run measure -- URL` | Печатает каждый запрос и итог |
| TUI | `npm run tui -- URL` | Показывает прогресс в терминале; без URL запросит адрес |
| Web UI | `npm run dev` | Открыть http://localhost:3000 |

Примеры с Makefile:

```bash
make cli URL=https://example.com/large-image.jpg
make tui URL=https://example.com/large-image.jpg
make dev
make test
make build
```

## Конфигурация и таймауты

Скопируйте `.env.example` в `.env` и измените значения при необходимости:

```bash
cp .env.example .env
```

| Переменная | Значение по умолчанию | Назначение |
| --- | ---: | --- |
| `METER_URL` | пусто | URL для CLI и TUI, если не передан аргументом |
| `METER_REQUEST_TIMEOUT_MS` | `15000` | Максимум для одного ответа, включая полную загрузку тела |
| `METER_TOTAL_TIMEOUT_MS` | `120000` | Максимум для всех десяти запросов вместе |

Для одного запуска можно передать переменные прямо в команду:

```bash
METER_REQUEST_TIMEOUT_MS=5000 METER_TOTAL_TIMEOUT_MS=30000 make tui URL=https://wallpapers.99px.ru/wallpapers/tags/8k/
```

Веб-интерфейс использует те же таймауты. Docker Compose также принимает их из `.env` или окружения.

## Docker Compose

```bash
make up
# открыть http://localhost:3000
make down
```

Compose собирает production-образ Next.js и публикует веб-интерфейс на порту 3000. Для CLI и TUI используйте локальный Node.js. Порт привязан к `127.0.0.1`.

## Как считается скорость

- **Среднее время:** сумма длительностей десяти запросов / 10, в миллисекундах.
- **Общий объём:** сумма реально прочитанных байтов, в десятичных мегабайтах (1 МБ = 1 000 000 байт).
- **Скорость:** общий объём × 8 / сумма длительностей, в **Мбит/с** (1 Мбит/с = 1 000 000 бит/с).

Время включает ожидание ответа и полную загрузку его тела. Если сайт показывает страницу подтверждения человека, инструмент сообщает об этом и прекращает замер; автоматическое прохождение CAPTCHA не предусмотрено. Страница каталога, например `https://wallpapers.99px.ru/wallpapers/tags/8k/`, измеряет загрузку HTML, а для оценки скорости лучше дать прямую ссылку на большой файл. HTTP-ошибка или таймаут останавливает замер с понятной ошибкой. Результат отражает скорость загрузки **конкретного сервера и файла**, а не предельную пропускную способность линии. Нулевые и очень маленькие файлы для замера не подходят.

## Проверка

```bash
npm test
npm run build
```

Тесты проверяют формулы и URL, а интеграционные сценарии поднимают локальный HTTP-сервер, проверяют порядок запросов, объём потокового ответа и обработку HTTP-ошибок.

## Структура

- `src/measure.js` — измерение и расчёт, общие для всех режимов.
- `src/cli.js` — консольный вывод.
- `src/tui.js` — интерактивный терминал.
- `app/` — интерфейс Next.js и потоковый API.
- `tests/` — unit и интеграционные тесты.

Веб-интерфейс предназначен для локального запуска. Не публикуйте его как открытый сервис без ограничения адресов запросов: он принимает URL от пользователя.
